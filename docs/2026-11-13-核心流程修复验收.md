# 核心流程修复与验收

本轮按用户确认，优先修复前次系统测试中的六个核心断点。原始审计报告保留，描述修复前状态；本文件记录当前修改与验证。本轮未推送GitHub，未改动正式业务资料。

| 原问题 | 当前处理 |
|---|---|
| U01 优化结果与报告断链 | 简版优化结果与历史记录可打开对应图文报告，展示该轮真实选课、投入和缺口变化；没有完整专业、就业基线时不补造四年预测 |
| U03 查看A却报告显示B | 报告明确引用所选专业决策或优化记录；从结果进入及侧栏查看沿用所选记录；校验本校归属，身份切换清除引用 |
| U04 非活动岗位影响高校缺口 | 使用共用active_job规则，草稿、暂停、结束、归档、删除等不进入活动需求统计 |
| E01 淘汰与关闭状态仍被分配 | 分配入口过滤非活动岗位、撤回与declined候选；恢复有效状态后可重新参与新分配 |
| E02 面试完成仍不能复核 | 预设题关联问题ID与岗位版本；结束后学生可核对编辑并明确确认提交，复用原测评答案和历史/复核失效规则 |
| E03 通话并发信令冲突 | 同轮ICE信令事务追加，与文字revision分离；前端串行发信令，先发布描述再发ICE；保留旧轮次拒绝和撤回权限校验 |

## 使用入口

高校：完成“培养方案优化”后点击“查看本轮图文报告”；历史优化记录也提供对应报告入口。在专业调整决策运行或查看某次结果后，可以打开该次报告。简版报告会明确显示缺口前后与资源占用，完整三情景推演仍需补齐有依据的高级决策输入。

学生：完成企业预设面试后，核对逐题回答，勾选确认并提交企业复核；企业再从原测评复核入口检查这些回答。不会未经学生确认自动将对话提交为测评答案。

企业：淘汰候选或暂停/结束岗位后重新计算招聘分配，对应组合不再新增占用建议预算。本轮没有引入正式录用、入职或持久招聘计划功能。

## 验证范围

测试均使用隔离数据库、合成业务材料和真实Edge。新增针对性测试先复现原失败，再运行修复版本；计算使用真实求解器。真人音频专项使用浏览器合成设备及真实WebRTC音轨和信令，不代表物理麦克风听音或公网跨网验收。

未纳入本轮：培养JSON向导、图文PDF导出、应届资格字段、企业邀约排期与正式录用闭环、招聘计划保存比较、课程映射编辑以及完整UI重设计。这些仍按前次清单后续处理。

## 实际验证结果

- 最终联合回归72项通过（26.64秒，退出码0），覆盖新增三组核心API测试及原报告、招聘、匹配、专业决策、并发和需求统计测试。非全仓库回归。`git diff --check`通过。

- 高校原报告、新引用与归属API、新完整Edge及原报告浏览器：同一进程14项通过，退出码0。包括简版实际填写计算→本轮报告→历史重开、A/B决策切换、移动布局及身份清引用。
- 最终文案调整后，新高校Edge两项再次同进程通过（26.90秒），额外验证真实UI退出并注册第二高校后不携带旧引用、旧课程动作；空基线保持未知。
- 面试原体验、新答案/版本/撤回API及真实双Edge：10项通过。预设核对提交后形成可复核答案；两种接通顺序均双端connected、有音频RTP、界面已接通且错误为空；每轮信令全部200。
- 招聘真实求解器集成覆盖先选中、淘汰移除、恢复可选、暂停/结束/草稿移除及恢复招聘重新可选；高校过滤覆盖五种非活动标记。

验证期间曾复现Windows原生access violation；没有将分进程通过作为稳定性证明。基于[HiGHS官方问题记录](https://github.com/ERGO-Code/highs/issues/2885)采用仅Windows单线程的运行缓解，实际高校多次求解与浏览器测试已在同进程正常完成，未改变目标与约束。该现象与原生并行问题吻合，未取得原生转储确认唯一根因；单线程可能降低较大模型的求解速度。SciPy提示threads为转交HiGHS的选项警告，未吞掉该提示或任何求解失败。
