# 语音朗读兼容修复

截图中的异常来自朗读接口，不是 SenseVoice 识别失败。原 `/api/voice/speak` 在非 Windows 平台直接抛出 ValueError，接口又将其包装为“本地中文语音合成未完成”。Linux/AWS 无法执行 Windows SAPI。

## 当前行为

- 页面先查询合成能力。Windows 服务器保留原 SAPI；Linux 以及服务器合成返回503时，使用访问者设备的中文语音。
- 新增 `web/device-speech.js`，只选择 `localService=true` 的中文语音，等待语音列表加载；不会自动调用外部云端语音。
- 设备朗读开始、结束时切换水滴状态。重播、关闭、开始录音及切换页面会取消旧播报；迟到回调不重新激活窗口。
- 缺少语音包、自动播放被阻止和启动超时均提供操作提示，保留录音、文字编辑、回答提交入口。
- 服务不可用返回503，空白文字返回422，认证检查保留。录音通过本站服务识别，页面与状态接口不再声称云端部署时音频始终留在访问者设备。

## 使用与部署

本轮仅本地修改与验证，没有提交、推送 GitHub 或部署 AWS。线上须同步本轮前后端代码并重启服务后生效，必须包含新增的 `web/device-speech.js`。

设备需具备本地中文语音包；浏览器阻止自动播放时点击“重播问题”。公网麦克风权限仍要求可信 HTTPS，HTTP IP地址的麦克风限制与本次中文朗读异常分别处理。未宣称完成 AWS 线上或真实手机验收。
